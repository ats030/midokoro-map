# 「土地のつながりをたどる」の生成実験

記事の材料と下書きをJSONで保存し、共通のHTMLテンプレートでプレビューを作る。
今回の範囲は、候補の選択、公式資料の照合、Ollamaによる下書き、構造検査までである。
公開アプリの更新と定期実行の登録は含めない。

```mermaid
flowchart LR
    C[候補と事実メモ] --> S[公式資料の変更検査]
    S --> P[地点・関係・出典のJSON]
    P --> O[Ollamaで1回生成]
    O --> V[構造・引用ID・数字の検査]
    V --> D[非公開の下書きとプレビュー]
    D --> H[人による出典確認と編集]
    H --> A[将来の公開処理]
```

## 材料の範囲

[候補カタログ](story-candidates.json)に、新規5テーマと15地点の事実メモを収録した。
メモは公式資料を読んで書いた短い説明であり、AIによる確認と人による確認は区別する。
現時点の確認者はAIで、人の確認は未完了である。
取得時には地点別の節を正規化し、確認時に固定したハッシュと照合する。
キーワードが残っていても節の内容が変われば、材料の再確認が必要になる。
この照合は意味の正しさを証明する検査ではない。
元のメモを機械的に新しい原文へ追従させる処理も含まない。

関係はすべてテーマによる比較に限定した。
資料にない共通の成因、年代、物の移動経路は関係にしない。
座標は今回の新規テーマでは未確認として空にしている。
プレビューは記事を読めるが、未確認座標がある場合は地図を有効にしない。
既存3テーマの形式と地図表示を保つ回帰検査を別に実施する。

## 実行

Python 3.12以上とローカルOllamaを使う。
Pythonの追加依存関係は不要である。
検証したモデルと利用条件は[ライセンス確認](story-tool-license.yaml)に記録する。

```sh
python3 scripts/story_pipeline.py
python3 -m unittest discover -s scripts -p 'test*story*.py'
```

候補順に未試行の1件を選び、1回だけ生成する。
特定の候補を選ぶ場合は `--slug izu-volcanic-landforms` を指定する。
出力と試行履歴はGit管理外の `.local/story-experiment/` に保存する。
各試行の `draft/review.md` に、本文と引用した事実を並べる。
`draft/manifest.json` にはモデルのdigest、入力とプロンプトのハッシュ、処理時間、トークン数を記録する。
公開済みの記事を出力先に指定することはできない。

HTMLを見る場合は、対象試行の `draft/preview` ディレクトリだけをローカルで配信する。

```sh
python3 -m http.server 8542 --bind 127.0.0.1 --directory .local/story-experiment/runs/<fingerprint>/draft/preview
```

`<fingerprint>` は実行結果に表示された値に置き換える。
資料の取得結果と他の試行を含む親ディレクトリは配信しない。

候補、出典の固定ハッシュ、モデルのdigest、生成コードと設定が同じなら再生成しない。
日付が変わっただけでは新しい入力と扱わない。
再生成を省略するときも出典の変更検査は実行する。
候補を指定しない実行では、出典の照合に失敗した候補を記録してから次の候補を調べる。
失敗した入力も自動では再試行しない。
同時起動はファイルロックで拒否する。
プロセス中断や通信失敗でサーバー側の終了が不明な場合は、その後の生成も停止する。
その場合はOllamaの処理状況と保存結果を確認し、履歴の未確定状態を解決する必要がある。
この履歴管理は同じ作業ディレクトリ内での保証であり、別マシン間の重複防止ではない。

## 検査が証明すること

生成結果に必要な項目、入力と同じ地点・関係ID、対象に許された引用ID、本文の数字を調べる。
HTMLでは生成文をエスケープし、資料側の出典URLだけをリンクにする。
これらに合格しても、引用先が本文の全主張を支えているとは限らない。
導入、見出し、問いも含め、固有名詞、成因、年代、因果関係を出典本文と照合する必要がある。
AIによる点検結果を、人が承認した記事として扱わない。

## 定期実行へ進む条件

今回の新規5テーマで、少なくとも4件が下書きになり、重大な事実修正がなく、人の確認・編集が1件10分以内に収まるかを調べる。
人の作業時間は実際の担当者の確認で測る。
AIの点検時間や生成時間を、その代わりに使わない。
少数の地形比較で成功しても、歴史・祭り・温泉へ同じ品質を一般化しない。

次段階では、確認済みの座標を付け、記事レジストリから一覧と配信対象を生成する構成へ移す。
スケジューラーが実行するのは1件の下書き生成までとし、公開は別の承認済み成果物から行う。
本番への移植と公開処理は、実験の結果を評価してから進める。

## 2026-10-14の結果

5テーマを各1回、既存の `gemma4:12b` で生成した。
自動再試行は行っていない。
4件が構造検査に合格し、1件は成功時の `error` が `none` だったため拒否した。
最初の失敗を受け、後半3件では成功・辞退の値をスキーマで限定した。
条件を固定した性能比較ではなく、実装を直しながら動作と失敗を調べた実験である。

| テーマ | 構造検査 | 生成時間 | AIの本文点検で必要と判断した主な修正 |
| --- | --- | --- | --- |
| 伊豆 | 拒否 | 104秒 | 本文の採用前に応答形式で拒否 |
| 室戸 | 合格 | 183秒 | 港の深さや岩の組成を見るだけで由来が分かるような、根拠のない観察方法を修正 |
| 隠岐 | 合格 | 99秒 | 異なる島の地点を、同じ島・岩質という前提で読ませる導入を修正 |
| 島原 | 合格 | 85秒 | 導入の文体を整理 |
| 手取川 | 合格 | 121秒 | 岩の形成と洪水による運搬を混同する結論と問いを修正 |

時間はOllama呼び出しの待ち時間を含み、編集時間ではない。
表の修正はAIが必要と判断した事項で、下書きの修正完了や人の承認を意味しない。
数値とモデル・プロンプトの記録は[実験結果JSON](story-experiment-results.json)を参照する。

4件中2件に、関係の説明を変える必要がある事実上の問題が見つかった。
人の確認・編集時間は未計測である。
そのため、定期公開へ進む条件は満たしていない。
同じ白山テーマの再実行では、出典を再確認したうえで生成を省略できた。
既存3パケットの回帰検査を含む25テストと、公開検査の4テストは合格した。
mediumレビューで見つかった出典再確認と候補選択の問題は修正し、回帰テストを追加した。

次段階の確認はBeadsの `ats030-ay530` で管理する。
現時点で使えるのは、少数の事前に材料を用意したテーマの下書き生成である。
新しいテーマや出典を無制限に発見する仕組みと、自動公開の品質は検証していない。
