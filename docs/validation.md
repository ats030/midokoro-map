## データの隔離

Goテストは一時ディレクトリで実行し、SQLiteは架空の入力から生成しました。
生成物を元のアプリやこの公開リポジトリのデータへ書き戻しません。
テスト時は広告の設定を空にし、要約の新規生成も無効にします。

実データ1919件と特定の品目の座標を検査する `internal/tokusan/services/tokusan_service_test.go` は収録していません。
これは本番カタログを再配布しない収録方針によるもので、その検査が通過したとは主張していません。
任意の元データがない場合にスキップする既存テストは、変更せずに結果へ残しています。

## 環境と実施していない確認

Python 3.12の既存仮想環境、Go 1.25.0、Node.js 24.19.0、既存のPlaywrightとChromiumを使いました。
サンドボックスがテスト用のローカルHTTP待受を拒否したため、Goテストと画面撮影はサンドボックス外で実行しました。
空の環境からの依存関係の再インストール、本番Workerへの配備、実地図の精度、写真取得、AI生成、料金枠の適合は今回確認していません。

公開検査では、ステージしたファイルを明示的な許可リスト、元のハッシュ、ファイルのモードと照合します。
高確度の認証情報パターンとローカル状態も検査しますが、全種類の秘密情報を検出する保証ではありません。
第三者の資産は元のバイト列とライセンス通知を維持し、通常の差分形式検査から分けます。

公開前のmediumレビューとGitHubへの反映結果は、作業のBeads課題へ記録します。
初回レビューで、展示の対象外のHTMLから外部リソースを読み込める点が指摘されました。
対象外の特集経路を拒否し、すべての応答に同一オリジンへ限定するCSPを付けました。
更新履歴のLAN計測タグも展示の応答から外し、ブラウザでこれらの経路を確認しました。
再レビューの指摘に合わせ、URLを正規化し、特集のファイルを展示の配信許可リストからも除外しました。
通常経路とエンコードされた別名の両方が拒否されることをブラウザで確認しました。
